# Lesson — 2026-09 kickoff plan correction

## What we believed

The first kickoff plan treated “build the studio” as “generate a Unity project + 13 GameFactoryCore stubs + pick Dock Rush.”

## What was wrong

| Charter rule | Mistake |
|--------------|---------|
| Build a machine, not one game | A starter kit plus one idea is not a repeatable OS |
| Never introduce a large framework for later | Empty Economy / IAP / Consent / RemoteConfig managers buy no learning |
| Never invent unverified package behavior | Hand-written `ProjectSettings` without an Editor likely would not open |
| Do not blindly clone | “2D docks instead of 3D screws” is presentation, not a mechanic |
| Feature must buy R/M/A/speed/learning | A fake template scene fails that test |
| Founder had no Unity install | “Open and compile” was a dead path |

## What we did instead

Shipped the **operating system**: charter, playbook, copy-paste templates for stages 0–10, knowledge base, a filled Stage 0–2 bet, and a Core **roadmap** with no C#.

Dock Rush may proceed only with all three unique-rule clauses: shared graph, color + facing, deadlock loss.

## Lesson for INDEX

Do not write unused infrastructure. Do not create Unity projects outside the Editor. Do not call a reskin a unique mechanic. The next game gets cheaper when templates and postmortems exist, not when empty managers exist.
